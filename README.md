# Familygram

> **English summary.** Familygram is a small, self-hosted, open-source family
> messenger: iOS, Android and web clients (Flutter) plus a single-binary Go
> server with SQLite. Login by phone number + SMS code, direct and group chats,
> photos, videos, files and voice messages, audio/video calls (LiveKit, TURN
> over TLS on 443). All traffic goes over one HTTPS port (443) on your own domain, so
> it looks like an ordinary website, and an optional relay can be placed in
> front. Deploy with `deploy/install.sh` (Docker + Caddy with automatic TLS).
> License: AGPL-3.0.

Семейный мессенджер, который вы разворачиваете на своём сервере. Простой
интерфейс в духе Telegram, приложения для iOS и Android, браузерная версия.
Рассчитан на семью и друзей, до нескольких десятков человек.

## Возможности

**Готово (MVP)**

* Вход по номеру телефона и коду из SMS. Посторонние номера войти не могут:
  номера семьи добавляет администратор.
* Личные и групповые чаты, «Избранное».
* Фото, видео, файлы, голосовые сообщения.
* Отметки «прочитано», индикатор набора текста, доставка в реальном времени.
* Веб-клиент открывается прямо по адресу сервера.
* Аудио- и видеозвонки, личные и групповые (этап 2, LiveKit).
* Push-уведомления о сообщениях на iPhone, напрямую через Apple, без Firebase
  (этап 3, см. «Push-уведомления»).
* Звонки на закрытый или заблокированный iPhone: системный экран звонка iOS
  (CallKit), ответ прямо с экрана блокировки (этап 3).

**В планах**

* Этап 3: push и звонки на закрытый телефон для Android, список зеркал
  сервера в клиенте.
* Этап 4: сквозное шифрование (E2EE), опционально.

## Быстрый старт

Нужны VPS с Ubuntu или Debian и домен. Три A-записи на IP сервера:
`family.example.com`, `rtc.family.example.com` и `turn.family.example.com`
(два последних — для звонков). Открытые порты: 80/tcp, 443/tcp, а для лучшего
качества звонков ещё 7881/tcp и 7882/udp.

```bash
git clone https://github.com/<owner>/familygram.git
```

```bash
cd familygram/deploy && sudo ./install.sh family.example.com +79990000000
```

Скрипт установит Docker (если его нет), создаст `deploy/.env` (и сгенерирует
ключи LiveKit для звонков), соберёт и запустит сервер. Сертификат Let's Encrypt выдаётся автоматически.

Дальше откройте `https://family.example.com` (или мобильное приложение с
адресом сервера) и войдите с номером администратора.

### Коды из SMS

Провайдер задаётся в `deploy/.env` переменной `FG_SMS_PROVIDER`:

| Значение | Что нужно указать                                   |
|----------|-----------------------------------------------------|
| `log`    | ничего; код только пишется в лог сервера (по умолчанию) |
| `smsru`  | `FG_SMSRU_API_ID` (sms.ru)                           |
| `smsc`   | `FG_SMSC_LOGIN`, `FG_SMSC_PASSWORD` (smsc.ru)        |
| `twilio` | `FG_TWILIO_SID`, `FG_TWILIO_TOKEN`, `FG_TWILIO_FROM` |

С провайдером `log` код читается так:

```bash
docker compose logs -f familygram
```

SMS стоят денег: каждый вход оплачивается у провайдера. На российские номера
надёжнее доставляют российские провайдеры (sms.ru, smsc.ru). Сервер
отправляет коды только на разрешённые номера и ограничивает частоту запросов,
поэтому лишних трат из-за флуда не будет.

После смены настроек перезапустите контейнеры:

```bash
docker compose up -d
```

### Добавление членов семьи

Администратор добавляет номера в приложении (Настройки → Семья) или
командой на сервере:

```bash
docker compose exec familygram familygram add-phone +79991234567 "Мама"
```

После этого человек входит по своему номеру и коду из SMS.

### Ручной запуск через docker compose

```bash
cd deploy && cp .env.example .env
```

Заполните в `.env` как минимум `FG_DOMAIN`, `FG_ADMIN_PHONE`,
`FG_LIVEKIT_API_KEY` и `FG_LIVEKIT_API_SECRET` (секрет — не короче 32 символов,
например `openssl rand -hex 32`), затем:

```bash
docker compose up -d --build
```

Данные (база SQLite и файлы) лежат в docker-томе `familygram-data`. Для
резервной копии достаточно сохранить этот том.

## Звонки

Аудио- и видеозвонки, личные и групповые, работают через
[LiveKit](https://livekit.io) — open-source медиасервер, который поднимается
тем же `docker compose`. Сервер Familygram отвечает за вызов, принятие, отбой
и историю звонков и выдаёт клиентам токены LiveKit.

Как идёт медиа (LiveKit сам выбирает первый рабочий путь):

| Путь | Порт | Комментарий |
|------|------|-------------|
| UDP | 7882/udp | лучшее качество, но чаще всего режется при блокировках |
| TCP | 7881/tcp | запасной прямой путь |
| TURN поверх TLS | 443/tcp (`turn.<домен>`) | выглядит как обычный HTTPS, проходит почти везде |

Порт 443 делится между сайтом и TURN по имени в TLS (SNI): Caddy собран с
модулем [caddy-l4](https://github.com/mholt/caddy-l4) и отправляет соединения
на `turn.<домен>` в LiveKit, а остальные — на сайт. Сигналинг звонков идёт
через `wss://rtc.<домен>`. Сертификаты для всех трёх имён Caddy получает сам.

Если звонки не соединяются (например, на мобильном интернете с жёсткой
фильтрацией), включите в приложении **Настройки → «Звонки только через
сервер»**: тогда медиа сразу идёт через TURN/TLS на 443.

**Звонок на закрытый телефон.** На iPhone входящий звонок звонит, даже если
приложение закрыто или телефон заблокирован: сервер будит телефон VoIP-push,
и iOS показывает свой экран звонка. Ответить можно прямо с экрана блокировки.
Нужен тот же ключ APNs, что и для уведомлений (см. «Push-уведомления»). Если
никто не ответил за 45 секунд, приходит уведомление «Пропущенный звонок».
На Android пока звонит только открытое приложение.

## Push-уведомления

Без push сообщения приходят, только пока приложение открыто. Для iPhone
сервер шлёт уведомления напрямую в Apple (APNs), без Firebase и других
посредников:

1. На developer.apple.com → Certificates, Identifiers & Profiles → Keys
   создайте ключ с галочкой «Apple Push Notifications service (APNs)»
   и скачайте файл `AuthKey_XXXXXXXXXX.p8` (скачать можно только один раз).
2. Положите его в `deploy/secrets/` (папка не попадает в git).
3. В `deploy/.env` укажите `FG_APNS_KEY_FILE=/secrets/AuthKey_XXXXXXXXXX.p8`,
   `FG_APNS_KEY_ID` (Key ID ключа) и `FG_APNS_TEAM_ID` (Team ID аккаунта)
   и перезапустите: `docker compose up -d`.

В уведомлении видны имя отправителя (или название группы) и начало
сообщения; на иконке приложения — число непрочитанных. Нажатие открывает
нужный чат. Пока приложение открыто, уведомления не показываются: новые
сообщения и так видны.

## Мобильные приложения

Клиент находится в `app/` (Flutter). Одно приложение работает с любым
сервером: адрес вводится на экране входа.

```bash
cd app && flutter pub get
```

```bash
flutter build apk --release
```

```bash
flutter build ios --release
```

Для iOS нужны Mac с Xcode и аккаунт Apple Developer (для установки на
устройства и публикации в App Store). Веб-версия собирается внутри
Docker-образа (`flutter build web`) и раздаётся самим сервером.

Для разработки сервер запускается локально:

```bash
cd server && FG_ADMIN_PHONE=+79990000000 go run .
```

## Устойчивость к блокировкам

* Весь трафик (сообщения, файлы, WebSocket и звонки) может идти по HTTPS
  на порт 443 вашего домена. Со стороны это обычный веб-сайт, на `/`
  открывается веб-клиент.
* Нет узнаваемых протоколов (XMPP, Matrix, MTProto) и нестандартных портов.
  Звонки при необходимости идут через TURN поверх TLS на 443, а не через
  голый UDP (см. раздел «Звонки»).
* Если блокируют IP сервера, перед ним можно поставить российский
  VPS-релей: [deploy/relay/README.md](deploy/relay/README.md).
* Гарантированно неблокируемого решения не существует: при «белых списках»
  на мобильном интернете работает только разрешённое. Подробности и
  ограничения описаны в инструкции по релею.

## Архитектура

Go-сервер одним бинарником (SQLite, файлы на диске, REST + WebSocket), LiveKit
для звонков, Caddy (с caddy-l4) для TLS, Flutter-клиент для iOS, Android и Web. Подробно, вместе с API и
форматом данных: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
